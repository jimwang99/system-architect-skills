# ALI-003: Cache invalidation timing gap
Date: 2026-07-26
Phase: testing
Status: draft

**What happened:** Feature tests passed locally but failed in CI because the cache was not cleared between test runs.

## L1: Cache state persisted across test runs
- **What we assumed:** Each test run started with a clean cache state.
- **What is actually true:** The shared Redis instance retained keys from the previous run; tests that relied on cache misses saw stale hits.
- **Evidence:** Evidence unavailable — no CI log retained; verification needed: rerun integration suite.
- **Why the assumption was wrong:** Test setup only cleared the application database, not the cache layer.
- **Class of error:** Test isolation failure
- **Improvement items:**
  - **P0 — Test harness:** `tests/conftest.py` — add Redis FLUSHDB call in session-scoped teardown fixture.
  - **P1 — AI agent skill:** `skills/testing/SKILL.md` — add cache-layer teardown to test setup checklist.
