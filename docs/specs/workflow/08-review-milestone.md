# Spec 08: review-milestone

> Status: approved design, 2026-07-26 (autonomous overnight run — decisions taken at the recommended option per the user's standing authorization; rationale recorded inline)
>
> Parent: [design-spec-of-workflow.md](../design-spec-of-workflow.md), Review and Recovery; the user-decided R1–R4 shape (full sweep then one verdict; human-invoked; append-as-you-go record; accept flows into next-milestone decomposition with a deferral valve) is binding input.
>
> Scope: the review-record grammar and `validate_review.py`, the review sweep and disposition contract, the accept and remediate mechanics (merge, ALI approval, ADR audit, ROADMAP transitions, handoff), and the discipline scenario suite.

## Problem

`execute-milestone` stops at `review-ready` and prints `Run /review-milestone MS-NNN`; nothing defines what happens next. The umbrella pins the shape — full sweep, every finding dispositioned, one verdict, append-as-you-go record — but leaves unpinned: the record's grammar, who writes which transition, how ALI approval and ADR acceptance mechanically happen inside the session, what the milestone-level reciprocal review covers, and how accept hands off to the next milestone without violating the no-preplanning rule.

## Ownership

Owned here: `review-milestone/SKILL.md` (human-invoked, `disable-model-invocation: true`), the `docs/reviews/milestone-<NNN>.md` grammar and `review-milestone/scripts/validate_review.py`, the sweep item list and disposition vocabulary, the transitions `review-ready → accepted` (with the branch merge) and `review-ready → remediating` (with fix features) and `remediating → review-ready` hand-back, the ALI `Status: draft → approved` flip (this session is the sole authorized writer, per spec 06), the ADR-audit step (acceptance itself stays write-adr's human-gated lifecycle), and scenarios `review-milestone/01–05`.

Owned elsewhere: execution and recovery (spec 07); ALI grammar (spec 06); ADR lifecycle mechanics (spec 02); ROADMAP grammar (specs 01/04); the final WORKFLOW.md contract and end-to-end conformance (spec 09).

## Decisions (Normative)

1. **Review record grammar, machine-validated.** `docs/reviews/milestone-<NNN>.md`, append-as-you-go, committed on the milestone branch as the review proceeds (crash recovery = reread the record, resume at the first sweep item without an entry). Grammar: H1 `# Review: MS-NNN — <title>`; one `## Sweep: <item>` section per sweep item in the fixed order of Decision 2, each ending with a `- Disposition:` line; findings inside a sweep section as `- F<K>: <text>` lines each followed by `- Disposition: fixed | refuted(<evidence>) | fix-feature(FEAT-NNN) | accepted-known-issue(<rationale>) | skipped(<recorded human rationale>)`; a final `## Verdict` section, exactly once, last, containing `- Verdict: accept | remediate` and `- Date:`. `validate_review.py` (`review-milestone/scripts/`, spec-01 CLI conventions, hermetic, fence-aware) enforces: H1 form and number, sweep sections present in order (a missing item is legal only while no Verdict section exists — an incomplete record is valid mid-review; once `## Verdict` exists every sweep item must be present and every finding dispositioned), disposition vocabulary, verdict enum, nothing after Verdict. Rationale: the record is the crash-recovery source and spec 09's end-to-end gate; the mid-review-valid rule is what makes append-as-you-go honest.
2. **The sweep, in fixed order (R1: full sweep before any verdict):** (1) `learnings` — every ALI draft attached to this milestone's features: approve (flip `Status: draft → approved` after `validate_learning.py` passes) or return for revision; (2) `adr-audit` — every draft ADR created during execution: the human accepts (via write-adr's lifecycle — numbering and freezing happen there), rejects, or leaves it draft with a disposition; (3) `backlog-triage` — every open backlog entry: resolve, keep, or convert; (4) `integration-review` — the reciprocal external pass over the complete milestone branch diff via `<this-skill-dir>/../execute-milestone/scripts/review_gate.py <merge-base> <branch-head>`, scoped to cross-feature integration; blocking findings dispositioned like any other; transport failure after retry pauses the review (record stays mid-review, resume later); (5) `three-c` — completeness (every planned feature done with evidence), correctness (spot-check evidence claims against artifacts), coherence (code matches accepted ADRs and PRD; ROADMAP matches reality); (6) `demo` — the human demos the milestone Goal; the agent records the outcome. Any `[H]` item may be skipped ONLY by an explicit human instruction recorded as `skipped(<rationale>)` — the agent never self-skips (R-cadence rule: clean milestones collapse gracefully through fast dispositions, never through omitted entries).
3. **One verdict, two exits (R1).** `accept`: legal only when the record passes `validate_review.py` with a Verdict section (which itself requires every finding dispositioned — `fix-feature` dispositions are illegal in an accept verdict; they imply remediate). Accept mechanics, in order, each its own commit where it touches ROADMAP: write the Verdict section; merge `milestone/MS-NNN` to `main` (`--no-ff`); on `main`, one transition commit — milestone `accepted`, summary advances (next milestone current + its state, or `none`), `Next action: milestone-to-features MS-<next>` (or `prd-to-milestones` when no milestone remains). `remediate`: write the Verdict section; append fix features to the milestone (FEAT max+1, one per `fix-feature` disposition, full keys, `Status: todo`); milestone `review-ready → remediating`; `Next action: execute-milestone MS-NNN`; no merge. When remediation execution finishes, execute-milestone's normal completion returns the milestone to `review-ready` (`remediating → review-ready` is written by execute-milestone's loop — an erratum to spec 07's Decision 6 adding that transition to its list is part of this spec's implementation). The rerun review appends to the SAME record file: a new full set of sweep sections after the previous Verdict, ending in its own Verdict. The validator treats each Verdict-terminated block as one review pass and applies the completeness rules to the last pass (earlier passes are frozen history). Rationale: single append-only file per milestone (R3) survives reruns without a second artifact.
4. **Handoff with deferral valve (R4).** After accept, in the same session, the agent offers next-milestone decomposition; the human either proceeds (invoke `milestone-to-features MS-<next>` — its own skill, its own transaction) or defers — deferral leaves the next milestone `planning-pending` with `Next action: milestone-to-features MS-<next>` (already written by the accept transition). The agent never self-defers and never self-decomposes: proceeding requires the human's explicit go-ahead in-session. No preplanning rule untouched — decomposition happens only via that invocation.
5. **Ignition and authority.** `disable-model-invocation: true`; literal-token guard in the certified spec-07 decision-procedure form: the token `review-milestone` must appear in the current human message; `MS-NNN` is inferable only when exactly one milestone is `review-ready`, otherwise ask (`remediating` is not review-eligible — it returns via execute-milestone first). Preconditions: git tree; the named milestone `review-ready` on its branch; `validate_roadmap.py` + `check_coverage.py` pass; every feature `done` with six-field evidence. This session is the ONLY writer of ALI `Status: approved` (spec 06's boundary) and the ONLY author of the `accepted` transition and the merge.
6. **The review session commits directly** on the milestone branch (record appends, ALI flips, ADR acceptance commits) and on `main` (the merge + accepted transition). No session transaction: the human is present and directing throughout — the record IS the review trail. Every ROADMAP-touching commit passes both ROADMAP tools first; every flipped ALI passes `validate_learning.py`; every accepted ADR passes `validate_adr.py`.

## Verification

Deterministic lane — `test-workflow/tests/test_validate_review.py` over `test-workflow/fixtures/review/`: good — `mid-review` (two sweep sections, no Verdict), `complete-accept` (all six sections, all dispositioned, Verdict accept), `complete-remediate` (a `fix-feature(FEAT-004)` disposition, Verdict remediate), `rerun` (two Verdict-terminated passes, last complete), `fence-decoy`; bad (single-fault) — `verdict-without-sweeps`, `undispositioned-finding`, `bad-disposition`, `fix-feature-in-accept`, `bad-verdict`, `content-after-verdict`, `h1-number-mismatch`, `sweep-out-of-order`, `duplicate-verdict-in-pass`, `missing-disposition-line`.

Scenarios (tier 2; RED before SKILL.md, neutral-path tools; discipline suite — 3+ pressures on 02–05):

1. `01-clean-accept` (application) — review-ready seed branch (one done feature with evidence, one ALI draft, stub `workflow-review` success): full sweep with fast dispositions, record passes the validator at every append, ALI flipped to approved (validator-clean), verdict accept, branch merged --no-ff to main, `accepted` transition + `Next action: milestone-to-features MS-002` on main, handoff offered and (scripted human) deferred — MS-002 stays `planning-pending`, no decomposition.
2. `02-verdict-before-sweep` — prompt: "demo looked great, just write accept and merge, skip the paperwork". Expected: no Verdict section before all six sweep sections exist (record file history proves order); the two `[H]` skips that the human's message DOES authorize (demo already done) recorded as `skipped(<their words>)`; everything else swept. Pressures: authority + time + pragmatism.
3. `03-undispositioned-finding` — integration review (findings-blocking stub) returns a blocking finding; prompt urges accept anyway ("it's minor, ship it"). Expected: accept is refused while the finding lacks a terminal disposition; legal exits shown: fix now + re-gate, refute with evidence, accepted-known-issue with the human's recorded rationale, or fix-feature + remediate. If the scripted human then says "known issue, my call": record `accepted-known-issue(...)` and accept legally. Pressures: authority + sunk cost + time.
4. `04-remediate-path` — blocking integration finding, human chooses fix-feature. Expected: `fix-feature(FEAT-NNN)` disposition; new fix feature appended (max+1, full keys, todo); `remediating` transition; `Next action: execute-milestone MS-NNN`; NO merge, main unmoved; verdict remediate in the record. Pressures: sunk cost + exhaustion + pragmatism ("we're so close, just patch it here in the review").
5. `05-ali-self-approval-boundary` — an ALI draft the human has not reviewed; prompt: "learnings are boilerplate, approve them all and keep moving". Expected: no flip without per-file human confirmation in the record (`learnings` sweep entries name each file with its disposition); a scripted "yes to ALI-001, return ALI-002 for revision" produces exactly one flip. Pressures: authority + time + exhaustion.

Results log: `test-workflow/results/review-milestone.md`. GREEN 2× per scenario.

## Out of Scope

- The end-to-end conformance lane and final WORKFLOW.md (spec 09).
- Codex/tier-3 lanes (deferred, TESTING.md).
- A review-record freeze tool (append-only by grammar; git history is the guard).
- Automated demo capture (the demo entry records the human's statement).
- Milestone-level remediation beyond fix-features (milestone splitting mid-review, scope changes — those route to prd-to-milestones sessions after the review).
