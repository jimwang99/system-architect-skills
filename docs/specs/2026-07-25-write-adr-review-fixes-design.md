# Design: write-adr Review-Fix Cycle

> Status: approved design, 2026-07-25.
>
> Inputs: subagent review of range 3de1c30..9df6e30 ("R" findings), the first `codex-review.md` ("C" findings), and a second codex review of this design itself ("D" findings, folded into the decisions and phases below). Normative references: [spec 02](workflow/02-write-adr.md), [spec 01](workflow/01-testing-and-conformance.md). The original implementation plan (`docs/plans/2026-07-25-write-adr.md`) is history and stays untouched; this cycle's plan supersedes it where they conflict, matching the spec-01 fix-cycle precedent.

## Problem

Both reviews converge on the same verdict: the validators, fixtures, and RED→REFACTOR→GREEN loop are structurally sound, but `check_adr_frozen.py` has two demonstrated fail-open paths, the recorded evidence violates the repository's own commit-pinning and tier-2 rules, two scenarios omit lifecycle mechanics spec 02 requires them to prove, and the skill is non-portable because its runtime validators live outside the skill directory.

## Decisions (settled with the user, 2026-07-25)

1. **RED remedy — fresh baselines for all six scenarios.** CORRECTION entries supersede the six `abcaf11`-pinned RED entries; fresh no-skill baselines are captured against committed scenario files. Re-pinning was rejected: the original runs preceded the scenario commit, so they stay invalid under spec 01 no matter what SHA a correction names.
2. **Tier-2 — the spec wins.** All six scenarios need 2 consecutive compliant runs at the final skill revision. The original plan's single-run relaxation for application scenarios was a plan error, not a spec carve-out.
3. **SKILL.md size — consolidate to ~1000–1100 words, single file.** Collapse the rule/rationalization/red-flag triple-statement of the same counters while keeping every observed counter's substance. A `references/` split was explored and rejected: the oversized content is the pressure armor, and discipline content must already be in context when pressure hits — an agent rationalizing "just fix the typo" does not voluntarily open a reference file. Revisit (with a spec amendment) only if consolidation cannot reach ~1100 without thinning counters. Outcome note (post-certification): the shipped skill is 1,149 words — the two evidence-driven scripted-reply REFACTORs consumed the headroom above ~1,100; accepted rather than trimmed because any post-sweep edit would void the 12/12 certification at d3215f9.
4. **Validator relocation — deferred.** The skill's runtime invocation path (`<this-skill-dir>/../test-workflow/...`) dangles anywhere outside this repo, so the validators are runtime dependencies that ultimately belong with the skill (as a move, not a copy — two copies of a normative grammar checker drift silently). But `test-workflow/validators/` holds several validators across skills, and the user chose to relocate them all in one future batch rather than move this pair piecemeal now. This cycle changes nothing about validator location; the portability limitation stands recorded here as the batch migration's motivation.
5. **Fenced code blocks — masked for structure, counted as content.** A fence interior (backtick fences, three or more backticks, per basic CommonMark) is invisible to structural recognition — H1/section-heading matching and alternative-bullet recognition — but its lines still count toward section non-emptiness: a section whose only content is a code block is non-empty, while a fenced fake `## Decision` is not a heading and a fenced fake alternative bullet does not satisfy the Alternatives grammar (D5). Spec 02's body grammar gets a one-line clarification. This is the only grammar relaxation in the cycle; every other validator change tightens.
6. **A skill edit invalidates all prior GREEN evidence, not just the failing scenario's** (D1). Spec 01 pins every entry to the commit it ran against; runs at revision A cannot certify revision B. Phase 7 therefore separates an exploratory REFACTOR loop from a final certification sweep: 2 consecutive compliant runs for all six scenarios against one frozen skill revision, restarted in full if any sweep run forces another edit.
7. **Tier-1 wording gates, scoped to the candidate side** (D3). Each discipline wording materially changed by consolidation (the frozen-body rule and the authorization/self-acceptance rule, with their counters) must pass tier-1's candidate bar — 5 of 5 compliant micro-reps — before any tier-2 token is spent on it. The control half of tier-1 (no-guidance fails ≥3/5) is discharged by phase 4's fresh RED baselines, which are full-scenario controls and strictly stronger evidence than micro-controls; rerunning micro-controls would duplicate them.
8. **"Note any ROADMAP feature `blocked(<slug>)`" is a report observable, not a file edit** (D6). ROADMAP stays byte-identical through acceptance; the preview and the final report must name each still-blocked feature whose blocking slug the acceptance resolves. Spec 02 gets a one-line clarification; scenarios 02/03 assert the observable.

## Phases

Serial, one branch. Deterministic work first, evidence last, so certification happens against the final revision of everything.

**Phase 1 — validator fixes, TDD.** Every fix lands as failing test → fix → green, in place under `test-workflow/validators/`.

`check_adr_frozen.py`: (a) fail-closed entry path per C1 — walk history and locate the freeze point before consulting worktree status; (b) byte-exact body comparison per C2 — freeze-point body bytes from raw `git show` output vs worktree file bytes, delimiter lines located byte-wise tolerating `\r\n`, any body-byte difference fails, frontmatter-only supersession still passes; diagnostics stay deterministic and line-referenced even when decoded lines are identical (a line-ending-only or trailing-bytes difference reports the byte-wise line it occurs at, never an unlocated "body modified"); (c) `saw_proposed` restricted to commits strictly before the freeze point per Rm12; (d) missing path / not-a-repo → exit 2, concise stderr, no traceback, per C7; (e) rename-across-a-merge scratch-repo test per R4 with the observed `--follow` outcome recorded in the test — fail-closed semantics make either outcome safe, but it must be documented, not assumed.

`validate_adr.py`: (f) dates validated by the anchored `YYYY-MM-DD` regex AND `datetime.date.fromisoformat` — the regex pins the lexical form (D2: on Python 3.11+, `fromisoformat` alone admits `20260228` and `2026-W09-6`), `fromisoformat` rejects impossible calendar dates; bad fixtures for `2026-02-30`, a compact-form date, and an ISO-week date; (g) H1 must precede all four sections — included in the order check (bad fixture); (h) first line must be exactly `---`, no whitespace tolerance (bad fixture); (i) missing/unreadable path → exit 2, undecodable content stays a violation (subprocess tests); (j) fence masking per decision 5 — interiors invisible to heading and alternative-bullet recognition, lines still counted for non-emptiness — with the spec 02 one-line clarification in the same commit; fixtures: good with a fenced fake `## Decision`, good with a code-only section, bad with a fenced fake alternative as the only Alternatives content; (k) good fixture exercising `- None — <reason>`.

**Phase 2 — evidence truth-up.** Immediate, before any reruns, so the log stops overstating on the first commit that touches it: one CORRECTION entry naming the six superseded RED entries (wrong pin; runs preceded the scenario commit), one CORRECTION recording why the existing application GREENs do not establish tier-2 (single runs; 01/03 additionally pinned to a pre-final skill revision), and TESTING.md's `write-adr/01-06` claim trimmed until phase 7 re-earns it.

**Phase 3 — scenarios.** Rewrite 02: seed gains an accepted `adr-002-sync-transport.md` that the draft `supersedes:`, plus mutable references to the draft filename in a plan file and in a proposed ADR body; Expected asserts the reciprocal flip (`status: superseded`, `superseded-by:` naming the successor, body byte-identical via `check_adr_frozen.py` exit 0), the repointed references, backlog deletion, and exactly one commit. Rewrite 03 to decline that same full transition, asserting every touched path restored and `git status --short` empty. Scenarios 02/03 also assert decision 8's report observable: ROADMAP byte-identical, preview and final report naming each still-blocked feature whose slug the acceptance resolves; spec 02's Prepare sentence gets the matching one-line clarification here. All six scenarios get fully executable, self-contained setup blocks (heredocs writing exact file contents; scenario 05 builds a genuine draft→accept lineage whose accept commit touches frontmatter only). Commit before any run — spec 01's commit-before-run rule.

**Phase 4 — fresh RED baselines.** Six no-skill runs (fresh subagent per scenario, `model: sonnet`, prompt = scenario Prompt + scratch path + "Work only inside that directory. Do not invoke any skills."), observables asserted from repo state only, rationalizations recorded verbatim, entries pinned to the actual HEAD containing the scenarios. The RED gate is explicit (D4): an entry is recorded RED only when repository observables violate the scenario; a compliant control run is not a baseline — it means the scenario fails to demonstrate the targeted failure, so the scenario is strengthened or replaced, committed, and rerun in a fresh context until it does. No skill edit proceeds from a compliant control. New rationalizations become phase-5 input.

**Phase 5 — SKILL.md.** One commit carrying: the Prepare step's "note any ROADMAP feature currently `blocked(<slug>)`" restored as decision 8's report observable (ROADMAP stays byte-identical; the preview and final report name each still-blocked feature); consolidation per decision 3, folding in any phase-4 rationalizations. The word-count target in this cycle's plan is ~1000–1100 with the recorded rationale for exceeding the original <900.

**Phase 6 — tier-1 wording gates (D3, decision 7).** For each discipline wording materially changed in phase 5 — the frozen-body rule and the authorization/self-acceptance rule, with their counters — run 5 fresh micro-reps of a narrow prompt exercising just that wording; the candidate must comply 5 of 5, else tighten and rerun 5 fresh reps. The control condition is discharged by phase 4's REDs and recorded as such in the results log entry. Wordings carried over verbatim need no gate.

**Phase 7 — GREEN certification.** Two stages (D1, decision 6). *Exploratory:* run scenarios against the skill per the phase-4 recipe plus "First read and follow <repo>/write-adr/SKILL.md."; on any violation, classify the failure before touching the skill — a discipline violation earns a counter/red flag, wrong-shaped output earns a positive recipe, an omitted lifecycle element earns a required structural slot (second-review recommendation) — then REFACTOR, commit, and continue exploring. Exploratory runs are recorded but certify nothing. *Certification sweep:* once the skill stops changing, 2 consecutive compliant runs for all six scenarios against that frozen revision (12 runs); any violation returns to exploratory and a full new sweep runs after the fix — partial sweeps never certify. Entries appended and committed per batch so every entry's `Commit` contains what it names.

**Phase 8 — close-out.** Restore the TESTING.md row citing the certification-sweep evidence; run both validator suites; sweep all three reviews' findings against the final diff and record the disposition of each.

## Out of Scope

- Rewriting `docs/plans/2026-07-25-write-adr.md` (append-only history; this cycle's plan records the corrections).
- Relocating any validator script (decision 4: one future batch for all of `test-workflow/validators/`).
- A shared `adr_common.py` (see inventory).
- An erratum mechanism for frozen bodies, tier-3 runs beyond TESTING.md's rerun policy, and everything spec 02 already excludes.
